# Adoption and Outcome Metrics

AI tool activation or prompt volume does not prove engineering improvement. Measure whether a workflow changes outcomes while protecting quality, security, and team trust.

## Measurement Model

### Adoption

- Eligible engineers actively using the approved workflow
- Frequency by use case, not only by tool
- Teams with documented guardrails and trained reviewers

### Flow

- Time to first useful pull-request feedback
- Review and delivery cycle time
- Time spent finding documentation or ownership
- Manual steps removed from repeatable workflows

### Quality and Reliability

- Accepted versus rejected AI findings
- Defects caught before merge
- Change failure rate and production defects
- Incident recurrence and mitigation time
- Security or privacy issues associated with the workflow

### Experience

- Engineer and reviewer satisfaction
- Perceived cognitive load
- Trust in generated output
- Time spent correcting low-value output
- Clarity of accountability

## Experiment Design

1. Select one bounded workflow and user group.
2. Capture a baseline before changing the process.
3. Define the expected benefit and unacceptable failure conditions.
4. Run long enough to include normal variation.
5. Combine quantitative trends with interviews or surveys.
6. Compare value with review cost and introduced risk.
7. Decide to stop, redesign, continue, or standardize.

## Avoid These Traps

- Treating generated lines of code as productivity.
- Ranking individuals by usage.
- Celebrating speed without monitoring defects and rework.
- Comparing teams with different systems, maturity, or constraints.
- Ignoring the cost of reviewing incorrect output.
- Scaling before security, privacy, and ownership are clear.
